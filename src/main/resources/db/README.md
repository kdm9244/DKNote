# 데이터베이스 관리

2026-10-11 여행을 개인 소유로 전환했습니다. `trips.owner_id`로 접근을 제한하고,
일정·준비물·첨부파일·실제 지출은 보존합니다. 새 `travel_places`와
`travel_reservations`는 장소 보관과 예약 정보를 저장하며 예약 파일은 기존
인증된 준비물 첨부 저장소를 재사용합니다.

기존 DB 전환에는 `scripts/migrations/20261011-personal-travel.sql` 다음
`20261011-personal-checklist.sql`을 실행합니다. 두 SQL은 실제 서버를 멈추고
DB·파일을 백업한 뒤 적용해야 하며, 먼저 복원된 별도 DB에서 검증해야 합니다.
소유자가 없는 여행은 전체 이전을 중단합니다. 설문 4개·투표 3개·일정 대안·회비,
총 9개 테이블을 삭제합니다. 후속 `20261011-remove-retired-features.sql`은
백업한 구 팀·가입 관계 및 비어 있는 게시글·피드·사진 테이블 7개를 제거합니다.
게시글·사진 데이터가 발견되면 삭제를 중단하고 자료 이전을 요구합니다.
여행·일정의 제거된 보조 정보는 개인 보관 자료 및 메모에 남깁니다.

해외 지출과 예상 비용은 원래 통화와 금액, 1 외화 단위당 원화 환율을 저장합니다.
환율이 빠진 유료 항목이 있으면 해당 원화 합계는 미확정으로 반환합니다.
일정 기간을 줄일 때 제외되는 날짜에 일정이 있으면 이전을 요구하고 삭제하지 않습니다.
여행·일정·장소·예약·지출 수정은 저장 버전을 비교해 오래된 수정 요청을 거절합니다.

현재 테이블 구조의 기준은 `src/main/java`의 JPA 엔티티입니다. 애플리케이션은
`spring.jpa.hibernate.ddl-auto=update`로 필요한 테이블과 컬럼을 반영하며, 이 폴더의
SQL은 애플리케이션 시작 시 자동 실행되지 않습니다.

## 현재 JPA DDL 확인

`schema-current.sql`은 현재 JPA 엔티티만을 기준으로 Hibernate가 생성한 문서용
테이블 생성문입니다. 엔티티를 변경한 뒤에는 프로젝트 루트에서 다음 명령으로
갱신할 수 있습니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\generate-schema.ps1
```

이 과정은 실제 DB에 테이블을 생성하거나 삭제하지 않고 문서 파일만 갱신합니다.
`schema-current.sql`을 애플리케이션 초기화 SQL로 직접 사용하지 마세요.

기존 `schema.sql`은 2026-07-30 시점의 수동 스냅샷으로, 현재 엔티티에 없는 테이블과
외래키를 포함하고 있어 제거했습니다. 새 운영 환경으로 이전하기 전에는 Hibernate
자동 갱신 대신 Flyway 같은 버전 관리형 마이그레이션 도입을 권장합니다.

`cleanup-unused-legacy-tables.sql`은 현재 코드에서 사용하지 않는 빈 구형 테이블을
정리하기 위한 수동 스크립트입니다. 다음 안전장치를 포함합니다.

- 대상 테이블에 데이터가 한 건이라도 있으면 실행 중단
- 현재 JPA가 문자열로 사용하는 `category_id` 컬럼은 유지
- JPA에 매핑되지 않은 구형 `card_id` 및 고정지출 분류 컬럼만 제거
- 모든 변경을 하나의 트랜잭션으로 실행

실행 전에는 반드시 PostgreSQL 백업을 만든 뒤 내용을 다시 검토하세요.
