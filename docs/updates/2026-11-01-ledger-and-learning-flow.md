# 가계부 요약·기간 통계·투자 손익 정산과 학습노트 이동 개선

## 데스크톱 대시보드 재구성

- 세로로 큰 카드를 쌓던 요약 화면을 전체 본문 너비를 쓰는 업무용 배치로 변경했습니다. 데스크톱 상단에는 총자산·이번 달 사용액·월 수지·순자산 4개 지표를 한 줄로 표시합니다.
- 지출 흐름과 자산 구성, 최근 거래와 계좌 현황을 각각 좌우로 배치합니다. 지출은 실제 거래를 일별로 합산하고 지난달 동일 기간과 비교하며 누적·일별 표시를 전환할 수 있습니다.
- 거래 집계 통화를 선택할 수 있으며, 자산과 부채는 기존 환율 계산을 사용해 원화로 합산합니다. 환율 조회 실패 시 부분 합계를 전체 자산처럼 표시하지 않습니다.
- 지출·이체·손익 정산은 상단 도구 모음으로 옮기고 계좌 목록에서 상세 화면으로 바로 이동합니다. 독립 투자·부채 탭은 유지합니다.
- `frontend/tests/dashboard-desktop-ui.mjs`에서 1366·1440·1920px의 4열 지표와 2열 패널, 일별 차트·통화 전환·환율 실패·빈 화면·모바일을 검증합니다. 화면 캡처는 `.local/dashboard-desktop-qa`에 저장합니다.

## 화면 변경

- 가계부 첫 화면은 이번 달 사용액, 현재 총자산, 생활 계좌 잔액, 빠른 기록, 최근 거래 5건을 표시합니다. 사용액을 누르면 통계로 이동합니다. 기존 투자·부채 상세 대시보드는 탭으로 유지합니다.
- 생활 계좌 잔액은 입출금 계좌의 합계입니다. 총자산은 기존 외화 환산·투자 예수금 중복 방지 계산을 사용합니다.
- 빠른 기록에서 지출 입력, 계좌 이체, 투자 손익 정산을 실행합니다. 투자 계좌가 여러 개면 계좌를 먼저 선택합니다.
- 통계는 일간·주간(월요일 시작)·월간·직접 선택을 지원합니다. 종료일 전체를 포함하며, 직전 동일 일수의 사용액과 비교합니다. 통화별 수입·사용액·카테고리·거래 목록과 별도 투자 실현 손익을 표시합니다.
- 계좌 이체, 잔액 조정, 투자 예수금 입출금은 생활비 사용액에서 제외합니다. 비활성 부채 계좌의 과거 거래도 부채로 식별합니다.

## 투자 손익 정산

- 투자 계좌 상세의 `손익 정산`에서 거래를 개별 입력하지 않은 순손익을 기록합니다. 기존 잔액 대조 기능은 유지합니다.
- 최종 예수금 방식은 현재 장부 예수금과의 차액만 실현 손익으로 반영합니다. 추가 입금·출금과 이미 입력한 거래는 먼저 장부에 반영해야 합니다. 수수료·세금 차감 후 실제 예수금을 입력합니다.
- 예: 입금까지 반영한 장부 예수금 150만 원 → 최종 예수금 160만 원이면 미기록 이익 10만 원만 반영합니다. 동일 잔액으로 다시 정산하면 추가 손익이 없어 저장하지 않습니다.
- 보유 종목이 있으면 자동 차액 계산을 제한하고 증권사에서 확인한 미기록 순손익을 직접 입력합니다. 이 경우 양수는 수익, 음수는 손실입니다.
- 최종 예수금 방식은 오늘 날짜만 지원합니다. 직접 입력은 계좌 시작일부터 오늘까지 선택할 수 있습니다. 과거 시점의 예수금을 현재 장부와 비교하지 않습니다.
- 거래 내역의 `손익 정산` 필터와 `정산 수정`에서 순손익 수정·정산 취소가 가능합니다. 차액만 예수금에 반영하여 이후 거래를 보존합니다. 과거 일별 자산 스냅샷은 재작성하지 않고 현재 스냅샷과 거래일 기준 손익 통계를 갱신합니다.
- 정산은 수량·매입원가·종목별 세금 내역을 만들어내지 않습니다. 종목별 세금 계산에는 매매 기록과 증권사 자료가 필요합니다.
- 계좌 잠금, 조회 당시 잔액 확인, 수정 버전 확인, 신규 요청 식별자로 잔액 충돌과 재전송의 중복 반영을 방지합니다. 수정·취소 후 예수금이 음수가 되는 경우 원인을 확인하도록 저장을 거절합니다.

## 학습노트

- 저장 후 상세 화면에 저장 완료를 표시합니다. 돌아가기는 진입한 로드맵·목록으로 이동하고 검색·필터·페이지를 복원합니다.
- 변경 없이 나가면 즉시 이동합니다. 변경사항이 있으면 화면을 떠나기 전에 한 번 확인하며, 확인창 취소 시 편집을 유지합니다. 브라우저 뒤로가기와 새로고침에도 이탈 보호를 적용합니다.
- 로드맵 내부 자료 분류는 현재 목표와 하위 항목으로 제한하며, 자료 종류의 `전체` 표기를 `모든 유형`으로 변경했습니다.
- 전체 모아보기는 `노트·PDF 검색`으로 표시하고 전체 자료 검색·독립 자료 관리 용도로 유지합니다.

## 함께 수정한 부분

- 기존 거래 생성·조회·수정·삭제·계좌 통계의 사용자 소유권 확인을 보강했습니다. 거래 생성과 잔액 변경은 계좌 잠금으로 처리하며 거래 통화와 계좌 통화의 불일치를 거절합니다.
- 계좌 조회 실패를 숨기지 않고 재시도할 수 있게 했습니다.
- 서버 저장 성공 후 화면 갱신 실패를 다시 저장해야 하는 실패로 취급하지 않도록 신규 입력 흐름을 구성했습니다.
- 모바일에서는 기간 버튼을 한 줄에 배치하고 최근 거래와 통계에서 금액을 바로 볼 수 있도록 조정했습니다.

## DB와 검증

- Flyway 사용 환경: `V9__investment_profit_settlement.sql`로 투자 거래 유형 CHECK 제약을 확장합니다.
- 기존 `ddl-auto:update` 환경: `LedgerDatabaseMigrationRunner`가 같은 제약을 시작 시 갱신합니다. 신규 테이블이나 사용자 거래 데이터 이관은 없습니다.
- 관련 백엔드 테스트: `InvestmentSettlementTest`, `LedgerPeriodTest`, `TransactionIsolationTest`, `InvestmentCostCorrectionTest`, `InvestmentHoldingsViewTest`, `TransactionServiceTest`.
- 화면 회귀: `cd frontend; node tests/ledger-simplification-ui.mjs`. 개발 서버와 Chrome을 실행하고 모든 업무 API를 메모리 응답으로 대체합니다. 실제 사용자 데이터는 쓰지 않습니다. 화면 이미지는 `.local/ledger-simplification-qa`에 저장합니다.
- 프런트엔드 빌드·린트, 마이그레이션 버전 검사, 데스크톱/390px 모바일 신규 기능 및 기존 투자 화면 회귀 테스트를 확인했습니다. 전체 Maven 테스트 155개 중 151개가 통과했고 조건부 테스트 4개는 건너뛰었습니다. 로컬 PostgreSQL을 사용하는 통합 테스트도 통과했습니다. 운영 반영은 GitHub Actions 배포 결과와 Heroku 릴리스·기동 로그·헬스 응답으로 확인합니다.
